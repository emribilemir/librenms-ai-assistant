## 2. What `sut_adapter.py` connects to

Per the review verdict the adapter is thin.

```text
run_gold.py (harness, deterministic assertions)
    |
    v
sut_adapter.py   <- thin: resets SpyBackend trace, calls the REAL SUT
                    orchestrator, translates its output into the harness
                    trace (routes/planner/synthesis flags).
    |
    v
hybrid_poc.orchestrate()   <- the SUT decision layer (in the PoC):
    Qwen planner (librenms-qwen, think=false, structured output)
    -> resolver_candidate_v4.resolve_device / resolve_device_set
    -> route selection
    -> SpyBackend execution (get_device / get_ports / get_alerts / get_events)
    -> investigation/historical -> Qwen grounded synthesis (production
       system prompt from the Modelfile)
    |
    v
SpyBackend (records tool, args, order, returned data; prove per case)
```

The adapter contains no routing, no formatting, no investigation bundling, no
per-case logic, and no rescue of planner failures: if the real planner returns
malformed JSON the orchestrator emits `route=unknown` and the case fails.

LLM usage is reported with two independent flags:
- `planner_llm_called` — the Qwen planner ran (intent understanding). True for
  40/40 Gold and 16/16 Generated by design of the hybrid architecture.
- `synthesis_llm_called` — Qwen produced/reinterpreted the final answer
  (investigation / historical synthesis). This is what the harness checks as
  `llm_called`.

## 6. Fixes made (smallest general fixes)

1. **Planner taxonomy extended to the orchestration contract (general).**
   `hybrid_poc.PLANNING_SCHEMA_GOLD` adds `ports`, `alerts`, `events`,
   `historical_investigation` request types and `device_ports`/`device_alerts`/
   `device_events`/`historical_status`/`unsupported` intents; the system prompt
   adds the general rules: current-status phrasing always wins → `atomic_fact`
   (resolver decides identity), direct retrieval vs investigation separation,
   write → `unsupported`, past → `historical_investigation`, device_set only for
   explicit group language, bare device-like tokens → `atomic_fact`.
2. **`device_query` verbatim rule (general).** "copy the raw reference exactly as
   written; never truncate/complete/normalize" — fixes the B2 truncation class.
3. **Historical rule correction (general).** The base planner rule
   "past -> unsupported" is replaced with "past -> historical_investigation"
   and its example updated.
4. **Instrumentation (general).** `orchestrate()` emits
   `planner_llm_called` / `synthesis_llm_called` separately and records
   exact SpyBackend traces, timing, planner raw output, and Qwen synthesis
   input/output.

Regression coverage: `sut-results/test_units.py` (37 checks: route mapping,
gold schema enums, resolver single/device-set contract, formatters) — all pass.
`sut-results/test_resolver_contract.py` runs the resolver against the gold
fixtures. No Gold case, expected output, or harness file was modified.
